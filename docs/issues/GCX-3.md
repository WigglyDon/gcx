# GCX-3: Complete installation, source delivery and mobile release gates

## Purpose and sequencing

Track completeness and actual release suitability without blocking every Android
engineering step on iOS or turning policy research into the product itself.
Early source/resource audits support GCX-1; public binary/store release needs
separate explicit authority. No paid enrollment or submission is dispatched here.

Qualify the existing emulated GameCube boot and DSP route with bundled, appropriately
licensed resources; no unconditional Nintendo IPL first-run requirement. Verify
fonts/generated assets and notices. Source visibility alone does not establish
rights. Optional original firmware import stays private and explicit.

Provide exact modified core/dependency/source inventory and reproducible full
corresponding source for actual binaries. Preserve GPL and other obligations;
original MIT code, Rust translation or FFI does not erase inherited terms. Use
original gcx branding with no Nintendo/Dolphin impersonation or game artwork rights
assumed from testing. Review current terms before a real combined store release.

Qualify Android AAB/signing updates, current target/permissions, 4/16 KiB actual
native/JIT runtime behavior, accessibility, save export/import and recovery. Verify
no hidden donor network/telemetry services or native-core download path. Maintain
scoped access and no sham foreground keepalive.

When authorized Apple resources and a concrete scope exist, test ordinary signed
stock-iOS execution with no debugger-enabled JIT assumption, a real graphics path
and actual game/audio performance. DolphiniOS's current JIT limitation is evidence
of a gap, not our completed port or a permanent impossibility. Preserve the goal
and report actual platform availability honestly.

Do not submit or publish binaries merely because this issue exists. Read
DISTRIBUTION and ACCEPTANCE, keep findings specific, and seek only genuinely new
consequential decisions. No separate worker is dispatched by this issue.
